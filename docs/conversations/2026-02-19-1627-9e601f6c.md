# Plan: AppPermissions model + Cancel feature

## Context

The permissions editor currently reads IAM policies from AWS every time a new draft is created, treating AWS as the source of truth. This makes "cancel" impossible — there's no stored baseline to revert to. We're introducing `AppPermissions` as the DB-side source of truth for an app+environment's current permissions, and a Cancel button that resets the draft back to that baseline.

## 1. New `AppPermissions` model

**File:** `devopshero_app/models.py` (add above `AppPermissionRequest`, around line 1078)

```python
class AppPermissions(models.Model):
    """The current (last-applied) permissions for an app in an environment."""
    id = models.UUIDField(primary_key=True, default=uuid.uuid7, editable=False)
    app = models.ForeignKey(App, on_delete=models.CASCADE, related_name="app_permissions")
    environment = models.ForeignKey(Environment, on_delete=models.CASCADE, related_name="app_permissions")
    statements = models.JSONField(default=list)
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        unique_together = [("app", "environment")]

    def __str__(self):
        return f"AppPermissions {self.app.slug}/{self.environment.slug}"
```

- **New function `cancel(app_permission_request, app_permissions)`:**
  - Reset `app_permission_request.statements` to `app_permissions.statements`
  - Save the request (keeps the draft and conversation intact, just undoes edits)

  - Accept `app_permissions` parameter
  - After setting status to `APPROVED_PENDING_APPLY`, also update `app_permissions.statements` from the request's statements and save
