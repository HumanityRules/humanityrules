The teardown's "delete EFS data" runs a one-shot Fargate task that does `rm -rf /mnt/efs/deployments/<app_slug>` on the env's EFS:


So in practice, for this template that single `rm -rf` deletes `…/checkpoint/rootfs.tar` (and the empty `checkpoint/` dir).

What it does **not** touch — worth flagging because it's the bulk of Hermes state at runtime:

- The **live persistent root** at `/var/lib/devopshero/hermes-roots/<app_slug>/` on the EC2 host (declared as a `host_mounts` entry in the template, mounted at `/hermes-persistent-root`). That's a host bind mount, not EFS, so it's outside this cleanup. It gets reclaimed only when the EC2 instance is replaced / its disk is wiped.
- The **policy-proxy sidecar** has no EFS mounts, so nothing of its state is on EFS anyway.

Compare with the DinD-based Hermes templates (`hermes-personal-docker`, `hermes-slack-docker`), which use `_HERMES_EFS_CONFIG` with two mounts (`home` → `/mnt/hermes-persistent`, `workspace` → `/workspace`) — there "delete EFS data" wipes both the home and workspace subdirs. The new `hermes_agent` deliberately moved the live root off EFS and onto the host, so EFS only carries the periodic snapshot.

**New behavior — delete EBS host data:**

The host bind mount lives at `/var/lib/devopshero/hermes-roots/<app_slug>/` on whichever EC2 container instance the task last ran on. Two complications:

1. The task is already torn down by the time `run_removal` executes the cleanup phase, so the bind mount is unmounted but the host directory remains on the instance's EBS volume.
2. ECS may have scheduled (and moved) the task across multiple instances over its lifetime, so the path can exist on more than one node.

The natural fit is **SSM Run Command broadcast to every instance in the env's ECS cluster**. The container instance role already has `AmazonSSMManagedInstanceCore` attached (`deploy_base.py:259`), so the permissions are there. The cleanup command would be:

```bash
test -d /var/lib/devopshero/hermes-roots/<app_slug> && rm -rf /var/lib/devopshero/hermes-roots/<app_slug> || echo "absent"
```

Run via `ssm.send_command` targeting `Key=tag:aws:autoscaling:groupName, Values=[devopshero-<env>-ecs-container-instance-asg]` (the ASG is created in `EcsClusterStack`), poll the command for completion, surface failures into `AppRemovalJob.status_message`. Instances that never ran the task get an `absent` and exit 0 — idempotent.

```433:481:devopshero_app/services/jobs/app_remove_executor.py
SSM_HOST_PATH_ALLOWED_PREFIX = "/var/lib/devopshero/"
SSM_COMMAND_TIMEOUT_SECONDS = 300
SSM_POLL_INTERVAL_SECONDS = 5
SSM_MAX_WAIT_ITERATIONS = 60  # 60 * 5s = 5 min


def _template_host_path_templates(template: "models.AppTemplate") -> list[str]:
    """Return distinct {app_slug}/{env_slug}-style host_mount source paths across all containers."""
    seen: list[str] = []
    for container in (template.containers or []):
        for mount in (container.get("host_mounts") or []):
            source_path = mount.get("source_path")
            if source_path and source_path not in seen:
                seen.append(source_path)
    return seen


def _resolve_host_paths(path_templates: list[str], app_slug: str, env_slug: str) -> list[str]:
    """Substitute {app_slug}/{env_slug} placeholders and validate the result is under the allowed prefix."""
    resolved: list[str] = []
    for template_path in path_templates:
        path = template_path.format(app_slug=app_slug, env_slug=env_slug)
        if not path.startswith(SSM_HOST_PATH_ALLOWED_PREFIX):
            raise ValueError(
                f"Refusing to clean host path outside {SSM_HOST_PATH_ALLOWED_PREFIX!r}: {path!r}"
            )
        if app_slug not in path:
            raise ValueError(
                f"Refusing to clean host path that does not include the app slug {app_slug!r}: {path!r}"
            )
        resolved.append(path)
    return resolved
```
