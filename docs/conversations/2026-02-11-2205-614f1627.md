**Root Cause Analysis**

There are three interacting issues:

**1. Eager `MainAgent.create()` on every conversation visit (~5s waste)**

In `_run_agent_loop`, `MainAgent.create()` is called immediately at startup — BEFORE checking whether there's a pending message:

```127:137:devopshero_app/services/agent/agent_runner.py
async def _run_agent_loop(runner: AgentRunner, conversation_id: UUID) -> None:
    # ...
    try:
        conversation = await Conversation.objects.select_related('organization', 'user').aget(id=conversation_id)
        runner.agent = await agent_service.MainAgent.create(conversation)  # <-- ALWAYS runs

        while True:
            pending_message = await get_pending_user_message(conversation)
```

`MainAgent.create()` does: DB queries, optional git clone, SDK client instantiation, and `await client.connect()` (which likely establishes a connection to the Claude API and resumes the session). This takes ~5 seconds and runs **every time you navigate to a conversation**, even when you're just reading old messages and there's no work to do.

If this call **fails** (API timeout, session error), the runner exits via the exception handler, sending a `None` sentinel to the event queue, which closes the SSE stream.

**2. EventSource auto-reconnects when the stream closes**

The browser's `EventSource` API has built-in automatic reconnection. When the first `stream/` closes (due to the runner crashing from a failed `MainAgent.create()`), the browser immediately opens a **second** `stream/` connection. The HTMX SSE extension doesn't use `sse-close`, so there's nothing to prevent this reconnection.

The second connection creates a new runner, which goes through `MainAgent.create()` again. If it succeeds this time, the runner enters an idle polling loop and the SSE stays open with keepalives — explaining the 1.8 minute duration (that's just how long you stayed on the page).

**3. Stale runner race condition in `ensure_agent_running()`**

There's also a race condition: if an old runner's task has completed but hasn't been removed from `_runners` yet (e.g., `shutdown()` has a 10-second drain timeout), `ensure_agent_running()` returns the stale runner. The event_generator connects to a dying runner's queue and quickly receives the `None` sentinel, causing the stream to close.
