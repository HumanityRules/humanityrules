## CDK Output Control Options

### The Problem

When CDK is invoked via subprocess from Python (as in your `cdk_utils.py`), the progress bar display optimized for interactive terminals doesn't render well. The progress bar uses terminal cursor manipulation that results in repeated/garbled output when captured as stream text.

### Solution 1: Use `--progress events` (Recommended)

The `--progress` flag controls how deployment progress is displayed:

- **`bar`** (default) — Shows a progress bar with the current resource being deployed. Uses terminal cursor control which breaks when captured via subprocess.
- **`events`** — Shows complete CloudFormation event history, line by line. Works well with subprocess capture.

```python
["npx", "--yes", "cdk", "deploy", "--all", "--progress", "events", "--require-approval", "never", ...]
```

### Solution 2: Use `--ci` flag

The `--ci` flag indicates CDK is running in a CI environment:

- Sends logs to `stdout` instead of `stderr`
- Modifies behavior for automated/non-interactive environments

```python
["npx", "--yes", "cdk", "deploy", "--all", "--ci", "--require-approval", "never", ...]
```

### Solution 3: Configure in `cdk.json`

You can set the progress mode in your project's `cdk.json` or global `~/.cdk.json`:

```json
{
  "progress": "events"
}
```

### Solution 4: Additional Output Control Flags

- **`--no-color`** — Removes ANSI color codes from output
- **`--verbose`** / `-v` — Increases output detail (can stack: `-vvv`)
- **`--no-notices`** — Suppresses notice messages (you already use this)

### Solution 5: CDK Toolkit Library (TypeScript/JS only)

AWS released `@aws-cdk/toolkit-lib` for programmatic CDK usage with full output control via an `IIoHost` interface:

```typescript
const toolkit = new Toolkit({
  ioHost: {
    notify: async (msg) => {
      console.log(`[${msg.time}] ${msg.level}: ${msg.message}`);
    },
    requestResponse: async (msg) => msg.defaultResponse
  }
});
```

**Limitation:** This library is TypeScript/JavaScript only — there's no Python equivalent. For Python, you must invoke the CLI via subprocess.

### Recommended Change for Your Code

In `cdk_utils.py`, add `--progress events` (and optionally `--ci`):

This will output each CloudFormation event as a separate line rather than trying to render a progress bar, which will integrate cleanly with your logging system.
