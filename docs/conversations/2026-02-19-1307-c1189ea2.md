**What's handled (`deploy_base.py`):**

`cleanup_rollback_complete_stacks()` runs at the top of `deploy_base.deploy()` and correctly deletes any of the three base stacks that are in `ROLLBACK_COMPLETE` before CDK/CF tries to create them:

```527:548:devopshero_app/services/infra_customer/deploy_base.py
def cleanup_rollback_complete_stacks(cf_client, env_slug: str) -> None:
    """Delete any ROLLBACK_COMPLETE stacks left by a previous failed provisioning attempt.

    CloudFormation stacks that fail during creation end up in ROLLBACK_COMPLETE — they
    still "exist" but are unusable. This must run before deploying so that CDK can
    create fresh stacks with the same names.
    """
    stack_names = [
        f"devopshero-{env_slug}-vpc",
        f"devopshero-{env_slug}-cluster",
        f"devopshero-{env_slug}-builder",
    ]

    for stack_name in stack_names:
        status = cloudformation_utils.get_stack_status(cf_client, stack_name)
        if status != "ROLLBACK_COMPLETE":
            continue

        logger.info("Stack '%(stack_name)s' is in ROLLBACK_COMPLETE, deleting before retry", {"stack_name": stack_name})
        deleted = cloudformation_utils.delete_stack_and_wait(cf_client, stack_name)
        if not deleted:
            raise RuntimeError(f"Could not delete failed stack '{stack_name}'")
```

**What's NOT handled (`deploy_app.py`):**

`deploy_app.deploy()` has no equivalent cleanup. It goes straight to checking if base stacks exist, then calling CDK. If any of the app-specific stacks (`{resource_prefix}-ecr`, `{resource_prefix}-app`, `{resource_prefix}-aurora`) are in `ROLLBACK_COMPLETE`, the CDK CLI will hit them and fail with an error like:

> Stack `doh-{env}-{app}-ecr` is in `ROLLBACK_COMPLETE` state and cannot be updated. Delete the stack and try again.

```600:612:devopshero_app/services/infra_customer/deploy_app.py
    cf_client = session.client("cloudformation")
    vpc_stack_name = f"devopshero-{env_slug}-vpc"
    cluster_stack_name = f"devopshero-{env_slug}-cluster"

```

There's also a secondary issue: `stack_exists()` uses raw `describe_stacks()` which returns `True` for `ROLLBACK_COMPLETE` stacks, so the VPC/cluster checks above would pass even if those stacks are broken — but that's actually fine because `deploy_base` cleans those up first before `deploy_app` ever runs.

**Summary of the gap:** You need a `cleanup_rollback_complete_stacks`-equivalent call at the start of `deploy_app.deploy()`, targeting the three app-specific stack names (`{resource_prefix}-ecr`, `{resource_prefix}-app`, `{resource_prefix}-aurora`). In Agent mode, this would be a small addition right after line 601 where `cf_client` is created.
