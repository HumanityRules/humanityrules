## Is this a bug?

It's behaving as designed but the design has a known wart for disconnected providers: 
- For **connected** providers, the broker's previous "force-refresh on every status read" bug was deliberately removed (see the comment on `_handle_unified_status`) because it was rotating GitHub refresh tokens on every page open.
- For **disconnected** providers there's no token to protect, so the "always refetch" behavior was left in. The cost is the noisy `[INFO] no integration row` log lines (and the 404s in the access log) every time someone opens Integrations.

## Assistant

Yes, with one important caveat that makes the design less obvious than MCP's.

The fundamental difference between the two paths is *where the state of truth lives*:

- **MCP**: refresh_token + client lives on the customer's container disk. "Connected?" is literally `os.path.exists(token.json)`. The broker IS the source of truth, so it can never be stale.
- **TLS-intercept**: refresh_token + DOH's OAuth client_secret live on DOH. DOH is the source of truth. The broker is a cache.

So the MCP path can be "free at status, refresh on tool call" because there's nothing to check — the local file *is* the answer. The TLS path has to derive its answer from somewhere, and that somewhere is DOH.

That said, you can still get there in spirit. Two flavors:

## Flavor 1: Negative-cache with TTL (small change)

The single line that forces a DOH round-trip on every status read for disconnected providers is here:

```144:150:template_repos/hermes_agent/doh_runtime/tls_intercept.py

            return False

            return False
```

Change it so `not_connected` / `revoked` entries are also considered fresh for some TTL (e.g., 5 minutes). Combined with the existing bootstrap (`_bootstrap_gateway_env` already calls `refresh_all` at startup, so the cache is warm before the control port opens), status reads after boot are zero DOH traffic.

What still works after this change:
- **User connects/disconnects via the WebUI's Connect / Disconnect buttons**: the OAuth return sentinel + the explicit invalidate call already bust the cache (see `init()` in `doh-integrations.js`).
- **Refresh button**: already calls `invalidate_all`.
- **Provider-side revocation (Google revokes the token)**: caught by the proxy hot path's `upstream_status == 401` eviction.
- **Container boot**: `_bootstrap_gateway_env` populates the cache.

What gets stale and recovers only after the TTL (or an explicit Refresh):
- User opens DOH in another browser tab and disconnects Google there, then comes back to the Hermes Integrations tab without going through the disconnect-with-rd flow.

This is a 5-line change.

## Flavor 2: Pure MCP-style (status never calls DOH)

Drop the "status read drives refresh" pattern entirely. `status_items()` reads only cache; the cache is filled by:
- Boot bootstrap (already there).
- Proxy hot path (existing — `token_for_host` → `_ensure_fresh`).
- Explicit invalidate-then-refresh from the WebUI (existing).

Same logical outcome as Flavor 1 with TTL=∞, but more honest about it: there's no implicit "let me peek DOH every time you look at the panel". You only get fresh state when something tells you state changed.

This means: if you stop the Integrations panel from posting `invalidate` after OAuth return (the JS already does this), there's no way for the broker to discover a connect/disconnect that happened *outside* its visibility. In practice this is fine — every connect/disconnect path in the product goes through one of:
- `/integrations/<slug>/start?rd=…` → sentinel → invalidate
- `/integrations/<slug>/disconnect?rd=…` → sentinel → invalidate
- WebUI Disconnect button → POST `vault/disconnect` → broker invalidates inline

The only escape hatch you'd want is the Refresh button (also already there).

## Recommendation

Go with Flavor 1 with a small TTL (60s or so).

- It's a 5-line semantic tweak, not a refactor.
- It keeps the "DOH is the source of truth" property — there's just a small staleness window.
- The TTL gives you self-healing for the "user disconnected on DOH in another tab" edge case without requiring them to click Refresh.
- The noisy log lines you started this thread with disappear: status reads collapse from N DOH round-trips per panel open to zero (after the first).
