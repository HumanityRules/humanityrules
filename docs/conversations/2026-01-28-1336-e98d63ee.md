## Diagnosis: Database Connection Exhaustion

The root cause is **PostgreSQL running out of connections**. Here's the breakdown:

### The Problem Chain

1. **Aurora Serverless v2 at minimum capacity (0.5 ACU)** → only ~45 available connections
2. **Django `conn_max_age=60`** → connections stay alive for 60 seconds
3. **Agent runner polls DB every 500ms** during active chat streams (line 175 of `agent_runner.py`)
4. **Long-running SSE streams** hold connections for the entire chat duration

When multiple users chat simultaneously, each SSE connection holds onto a database connection. The agent runner loop keeps the connection alive by polling the database. At minimum capacity, Aurora only has ~45 connections, which gets exhausted quickly.

The **SessionStore error** is a cascading failure — when Django's session middleware tries to load the session from the database, it can't get a connection and fails with `AttributeError: '_session_cache'`.

### Solutions (in order of impact)

1. **Immediate fix — Increase Aurora min capacity**: Change `serverless_v2_min_capacity` from `0.5` to `2` ACU. This gives ~180 connections minimum instead of ~45.

2. **Reduce connection lifetime**: Change `conn_max_age=60` to `conn_max_age=0` for now (closes connections after each request). This is suboptimal for latency but prevents exhaustion.

3. **Optimize agent runner polling**: The 0.5s polling interval with DB queries is aggressive. Consider increasing to 1-2 seconds or using a different mechanism (Redis pub/sub, database NOTIFY/LISTEN).

4. **Long-term — Add connection pooling**: Deploy PgBouncer in front of Aurora to manage connections more efficiently.
