## User

The command that manages EFS spins up a container that's too barebones. I need tools like vim, less, etc. Is it a base image issue?

---

## Assistant

Yes, it's a base image + command issue. The EFS browser uses `public.ecr.aws/amazonlinux/amazonlinux:2023` with a bare `sleep infinity` command:

```39:39:devopshero_app/management/commands/doh_efs_browse.py
CONTAINER_IMAGE = "public.ecr.aws/amazonlinux/amazonlinux:2023"
```

```268:268:devopshero_app/management/commands/doh_efs_browse.py
            "command": ["sleep", "infinity"],
```

Amazon Linux 2023 minimal ships with almost nothing — no `vim`, no `less`, no `tree`, etc. Since this is a task definition registered via the ECS API (no Dockerfile), the simplest fix is to make the command install useful packages before sleeping. That way the image stays generic and cacheable, and the tools are there when you shell in.

---

## Assistant

The container will now run `dnf install` on startup before entering the `sleep infinity` loop. Packages added:

- **vim-minimal** — vi/vim editor
- **less** — pager
- **tree** — directory tree viewer
- **findutils** — `find` and `xargs`
- **tar** / **gzip** — archive tools
- **procps-ng** — `ps`, `top`, etc.

The install adds ~10-15 seconds to the startup time (the command already waits for the task to reach RUNNING and for the exec agent, so the timing overlaps). Once you're in, everything is ready.

## Assistant

The `2023-full` variant is ~400 MB vs ~100 MB for the minimal one, so the first pull takes a bit longer — but Fargate caches images, so subsequent runs won't pay that cost. And you skip the `dnf install` wait entirely, which is a better trade-off for a debugging/browsing tool like this.
