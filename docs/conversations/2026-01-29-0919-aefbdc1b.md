## Diagnosis

**Root cause:** The `create_datastore` MCP tool description doesn't specify the valid values for the `deployment_mode` parameter.

**What happened:**
1. Agent called `create_datastore` with `deployment_mode: "serverless"` 
2. Tool rejected it with: `"Invalid deployment_mode 'serverless'. Must be one of: aurora_serverless_v2, aurora_provisioned"`
3. Agent corrected itself and called again with `deployment_mode: "aurora_serverless_v2"` — success

**The problem:**

Looking at the tool definition on lines 484-498 in `mcp_tools.py`:

```484:498:devopshero_app/services/agent/mcp_tools.py
@tool(
    "create_datastore",
    (
        "Create a managed database (datastore) in the selected workspace. "
        "Supports Aurora PostgreSQL and Aurora MySQL with Serverless v2 scaling. "
        "Requires a workspace in the conversation context."
    ),
    {
        "name": str,
        "engine": str,
        "database_name": str,
        "deployment_mode": str,
        "serverless_min_acu": float,
        "serverless_max_acu": float,
    },
)
```

The description says "Serverless v2 scaling" but doesn't tell the agent the exact parameter value to use. The agent reasonably guessed `"serverless"` instead of the required `"aurora_serverless_v2"`.

**Fix:** Update the tool description to explicitly list valid `deployment_mode` values:

```python
@tool(
    "create_datastore",
    (
        "Create a managed database (datastore) in the selected workspace. "
        "Supports Aurora PostgreSQL and Aurora MySQL. "
        "Requires a workspace in the conversation context. "
        "For deployment_mode, use 'aurora_serverless_v2' (recommended) or 'aurora_provisioned'. "
        "For engine, use 'aurora-postgresql' or 'aurora-mysql'."
    ),
    ...
)
```

The same pattern applies to `engine` — it should clarify whether to use `"postgres"`, `"postgresql"`, `"aurora-postgresql"`, etc.

Yes, there's a more expressive JSON Schema format. Looking at your own codebase, `deploy_app` already uses it:

```518:556:devopshero_app/services/agent/mcp_tools.py
@tool(
    "deploy_app",
    (
        "Deploy an application to AWS infrastructure. "

    ),
    {
        "type": "object",
        "properties": {
            "name": {"type": "string", "description": "Human-readable name for the app (used to derive slug for matching)"},

            "app_type": {"type": "string", "description": "Type of app: web, worker, or scheduled"},
            ...
        },
        "required": [
            "name", "app_type", "build_strategy", "container_port",
            "cpu", "memory", "health_check_path", "environment_slug"
        ],
    },
)
```

**The JSON Schema format is better for this use case because it supports:**

1. **Per-parameter descriptions** — Each param gets its own description text
2. **Enums** — You can constrain valid values:
   ```python
   "deployment_mode": {
       "type": "string",
       "enum": ["aurora_serverless_v2", "aurora_provisioned"],
       "description": "Deployment mode for the database"
   }
   ```
3. **Required vs optional** — Explicit `required` array separates mandatory from optional params
4. **Default values in descriptions** — Can document defaults without ambiguity

For `create_datastore`, converting to JSON Schema would let you add:
```python
"deployment_mode": {
    "type": "string",
    "enum": ["aurora_serverless_v2", "aurora_provisioned"],
    "description": "aurora_serverless_v2 (recommended) or aurora_provisioned"
},
"engine": {
    "type": "string",
    "enum": ["aurora-postgresql", "aurora-mysql"],
    "description": "Database engine"
}
```

This would prevent the agent from guessing wrong values entirely — the enum constraint makes it explicit in the tool schema that Claude sees.
