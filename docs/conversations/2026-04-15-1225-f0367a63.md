## Assistant

You don’t use classic SSH to Fargate. You use **ECS Exec** (`aws ecs execute-command`), which goes through **SSM Session Manager**. You need the [AWS Session Manager plugin](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager-working-with-install-plugin.html) for the CLI.

### DevOps Hero control plane (prod ECS)

**Run Django management commands in the running task** — yes, there is a wrapper:

```bash
cd infra_devopshero
./prod_manage.sh <command> [args...]
```

Examples: `./prod_manage.sh doh_query ...`, `./prod_manage.sh shell`, `./prod_manage.sh dbshell`. It picks the `doh-prod-app` task on `doh-prod-cluster` and runs `uv run python manage.py ...` inside the `devopshero` container via ECS Exec (see `infra_devopshero/prod_manage.sh`).

**Interactive OS shell (closest thing to “SSH”)** — use ECS Exec directly (documented in `infra_devopshero/AGENTS.md` under “ECS Exec (SSH Alternative)”):

```bash
TASK_ARN=$(aws ecs list-tasks --cluster doh-prod-cluster --service-name doh-prod-app --query 'taskArns[0]' --output text)

aws ecs execute-command \
  --cluster doh-prod-cluster \
  --task "${TASK_ARN}" \
  --container devopshero \
  --interactive \
  --command "/bin/bash"
```

Use your DOH AWS credentials (`DOH_AWS_*` from `.env` mapped to `AWS_*`) and region `us-east-1` as in that doc.

### Other “management command” in this repo

**`doh_efs_browse`** — not for the control-plane app. It assumes into a **customer** account, starts a **temporary** Fargate task with EFS mounted, then opens an interactive shell via ECS Exec to browse `/efs/deployments/...`. That’s EFS inspection, not “shell into the prod DOH service.”

### Customer-deployed apps

Those run in the **customer’s** cluster/service with their own names. There isn’t a single repo script like `prod_manage.sh` for arbitrary customer tasks; you’d use the same ECS Exec pattern with that account’s cluster, service, task ARN, and container name (and ECS Exec must be enabled on that service/task).

### Command: `doh_app_shell`

**File:** `devopshero_app/management/commands/doh_app_shell.py`

It follows the same pattern as `doh_efs_browse`: assume the customer role with `iam_utils.get_assumed_role_session`, then run **`aws ecs execute-command`** (interactive). That path is what people usually mean by “SSM” for ECS: the Session Manager plugin talks to ECS Exec.

**Identity (aligned with CDK):**

- **Cluster:** `devopshero-{env_slug}-cluster`
- **Service:** `doh-{env_slug}-{app_slug}` (see `deploy_app.py` `resource_prefix`)
- **Container:** `app_slug` (`container_name=app_config.app_name` in CDK)

**CLI:**

```bash
uv run manage.py doh_app_shell --account "<AWS account name or ID>" --app <app-slug>
uv run manage.py doh_app_shell --account "..." --org "<org slug or name>" --env prod --app <app-slug>
```

Optional **`--command`** (default `/bin/bash`) if the image has no bash.

**Checks:**

- Loads `Environment` for that account + `--env`, and `App` for that account’s org + `--app` slug (so typos fail early).
- Uses **`environment.aws_region`** for the assumed-role session (not hard-coded `us-east-1`).
- Picks the **first RUNNING** task from `list_tasks` for that service, waits for **RUNNING**, then for the **ExecuteCommandAgent**, then connects (with the same retry pattern as `doh_efs_browse`).

**Needs locally:** AWS CLI v2, Session Manager plugin, `DOH_AWS_*` in `.env`.

The `manage-commands` skill list now includes **`doh_app_shell`** for discovery.
