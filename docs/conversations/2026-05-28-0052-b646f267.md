## Assistant

The mount gives Hermes a **snapshot of host creds**, but it does **not** keep them fresh by itself. Two separate problems:

1. **Host file must be refreshed** — your `bedrock_dev` STS creds (~1h via `opsh`) expire on the host.
2. **`aws_signer` caches creds** — it builds one botocore `Session()` at startup and reuses it. Even after the mounted `~/.aws/credentials` updates, the signer may keep signing with expired tokens until restarted.

Production avoids this because ECS task-role creds are **RefreshableCredentials** via IMDS. Local mount is static STS in a file.

---

### Options (best first)

1. **Host refresh loop + signer reload (quick win)**  
   Same as Claude Code: run `opsh -c bedrock` on a timer (launchd/cron, ~every 45 min). The `:ro` mount is fine — host writes, container reads.  
   After refresh, restart the signer or container:
   ```bash
   docker compose restart hermes
   ```
   Or kill `aws_signer` inside the container if supervisor restarts it (today it likely does not — full restart is safer).

2. **Teach `aws_signer` to re-read creds (best fix)**  
   Small change to `aws_signer.py`: create a fresh `Session()` per request, or on upstream `ExpiredTokenException` invalidate cache and retry once. Then host `opsh` + bind mount is enough without container restarts. Matches how you'd want local dev to behave long-term.

3. **Host wrapper script**  
   One command for dev workflow:
   ```bash
   opsh -c bedrock && docker compose -f template_repos/hermes_agent/docker-compose.yml restart hermes
   ```
   Run manually when Bedrock starts failing, or from the same launchd job as (1).

4. **Skip the mount — inject env vars**  
   Put `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_SESSION_TOKEN` in `.env` (or export from an `awsCredentialExport`-style script). Works only if you have a refresh script updating `.env` and restarting compose. More brittle than the mount; only worth it if mount path is awkward.

5. **Long-lived IAM keys in `.env` (local only)**  
   Simplest if policy allows: static keys, no `opsh`, no mount. Not equivalent to your Okta/STS setup.

6. **`:rw` mount + refresh inside container**  
   Only if you want `aws sso login` / `opsh` running *inside* Docker. Usually worse on Mac — Okta/browser auth belongs on the host. Your compose comment already flags this.

**Pure compose can't fix the cache** — `aws_signer` holds one botocore `Session`; the mounted file can change but the signer won't notice. Compose can only trigger a **reload** (restart) or swap in a **refreshable credential source**.

---

### 1. Compose watch → restart on cred file change (compose-only)

When Claude Code / `opsh` rewrites `~/.aws/credentials`, restart Hermes so `aws_signer` picks up a new session:

```yaml
  hermes:
    develop:
      watch:
        - path: ${HOME}/.aws/credentials
          action: restart
```

Run with:

```bash
docker compose up --watch
# or: docker compose watch
```

**Pros:** no code changes, no sidecar.  
**Cons:** full container restart on each refresh; must use watch mode (not plain `up`).

---

### 2. Compose + short-TTL `credential_process` (no restarts, still no `aws_signer` change)

Split the mount so **credentials** come from the host but **config** is local-dev owned:

```yaml
volumes:
  - ${HOME}/.aws/credentials:/hermes-persistent-root/root/.aws/credentials:ro
  - ./docker/local-aws-config:/hermes-persistent-root/root/.aws/config:ro
  - ./docker/read-bedrock-creds.sh:/hermes-persistent-root/usr/local/bin/read-bedrock-creds:ro
```

`local-aws-config`:

```ini
[profile bedrock_dev]
region = us-east-1
credential_process = /usr/local/bin/read-bedrock-creds bedrock_dev
```

Script reads `[bedrock_dev]` from the mounted credentials file and prints STS JSON with **`Expiration` ~5 minutes ahead**. Botocore re-runs the process on refresh and reads the updated file — no signer change.

**Pros:** no container restart; picks up host refresh within TTL.  
**Cons:** one small script + config file (not strictly compose-only).

---

### 3. If compose-only is too rigid

One line in `aws_signer.py` — `Session()` per request instead of once at startup — is the smallest code fix. Still reads the same mount; no sidecar, no restarts.

---

**Recommendation:** try **(1)** first if brief restarts are OK and you want zero extra files. Use **(2)** if you want seamless pickup after host refresh without bouncing the container.

You're right to push back — a new `Session()` every Bedrock call would re-run the credential provider chain each time. That's unnecessary overhead on a hot path.

**Better options, latency-wise:**

1. **Retry on `ExpiredTokenException` only (best happy-path cost: zero)**  
   Keep one `Session`. When upstream returns expired token, invalidate the cached creds, re-read from the mounted file once, retry the request.  
   Normal requests: unchanged. You pay a refresh only after Claude/`opsh` has already updated the host file and Bedrock rejects the old token.

2. **`credential_process` with short `Expiration` (near-zero per request)**  
   Still one `Session`. Botocore re-invokes the helper only when creds are near expiry — not on every request. A 5-minute TTL means at most one subprocess + file read every few minutes, not per chat turn.

3. **mtime check before signing (tiny constant cost)**  
   One `stat()` on `/root/.aws/credentials` per request; bust the session's credential cache only when the file changes. Cheap, proactive (no failed Bedrock call first), but still one syscall per request.

4. **Compose watch → restart (zero runtime cost, disruptive)**  
   No signer logic change; container restart when the file changes.

**What I'd pick:** **(1)** for minimal code + no steady-state tax, or **(2)** if you want pickup without waiting for a failed call. Both avoid per-request `Session()` creation.

### Core idea

```python
def _reload_session_credentials(session: Session) -> None:
    session._credentials = None  # force botocore to re-read ~/.aws / task role

def _upstream_expired_token(upstream) -> bool:
    error_type = upstream.headers.get("x-amzn-errortype", "")
    return error_type.startswith("ExpiredTokenException")
```

Then in `_proxy`, after `urlopen` and **before** `send_response`:

```python
if (
    upstream.status == 403
    and _upstream_expired_token(upstream)
    and not retried
):
    upstream.release_conn()
    logger.info("expired AWS credentials; reloading and retrying once")
    _reload_session_credentials(session)
    # re-build AWSRequest, re-sign, urlopen again with retried=True
    ...
```

### Sketch of the touched region

Today `_proxy` is one linear path (sign → request → stream). It becomes:

```python
def _proxy(self, *, retried: bool = False):
    ...  # read body, build AWSRequest (unchanged)

    credentials = session.get_credentials()
    if credentials is None:
        self.send_error(500, "no AWS credentials available")
        return
    SigV4Auth(...).add_auth(aws_request)

    upstream = pool.urlopen(...)  # unchanged

    if upstream.status == 403 and _upstream_expired_token(upstream) and not retried:
        upstream.release_conn()

        if session.get_credentials() is None:
            self.send_error(500, "no AWS credentials available after reload")
```
