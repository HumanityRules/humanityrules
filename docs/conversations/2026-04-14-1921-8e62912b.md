## Assistant

The command is ready. Here's what it does:

**Usage:**
```bash
uv run manage.py doh_efs_browse --account "Humanity Rules Sandbox"
uv run manage.py doh_efs_browse --account "Humanity Rules Sandbox" --env prod
```

**How it works:**

1. **Assumes role** into the customer account using the existing `iam_utils.get_assumed_role_session` pattern
2. **Reads CloudFormation outputs** from the VPC and EFS stacks to get the filesystem ID, subnets, and security groups
3. **Creates/reuses an IAM task role** (`devopshero-{env}-efs-browser-role`) with:
   - SSM permissions for ECS Exec (`ssmmessages:*`)
   - EFS root access permissions (`ClientMount`, `ClientWrite`, `ClientRootAccess`) scoped to that specific filesystem
4. **Registers a Fargate task definition** — minimal 0.25 vCPU / 512MB Amazon Linux 2023 container with the EFS root volume mounted at `/efs` (no access point, so you see everything)
5. **Runs the task** with `enableExecuteCommand=True` and `initProcessEnabled=True`
6. **Waits for RUNNING** state (polls every 5s, up to 5 minutes)
7. **Opens an interactive bash shell** via `aws ecs execute-command --interactive`, passing the assumed role credentials as environment variables
8. **Cleans up on exit** — stops the task and deregisters the task definition (the IAM role is left in place for reuse on subsequent invocations)

The EFS root at `/efs` contains `/deployments/<app-name>/` directories — one per deployed app using the `fargate_web_efs` stack profile. Ctrl+C or typing `exit` in the shell triggers cleanup.

**Prerequisites:** AWS CLI v2 and the [Session Manager Plugin](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager-working-with-install-plugin.html) (`brew install --cask session-manager-plugin` on macOS).

**Root cause**: After a Fargate task reaches `RUNNING` status, the ECS Exec managed SSM agent (`ExecuteCommandAgent`) still needs time to initialize and register. Calling `execute-command` immediately after `RUNNING` hits the `InvalidParameterException`.
