What is pdp_mock?

---

## Assistant

**`pdp_mock`** is DOH’s **mock Policy Decision Point (PDP)** — a tiny, stdlib-only **AWS Lambda** under `lambdas/pdp_mock/` that behaves like `/api/pdp/evaluate` for **policy proxy end-to-end tests**.

**What it does**

- Behind an **ALB** it exposes **`POST /evaluate`** with JSON `app_id`, `oidc_sub`, `username`, and `path` (same shape as the real PDP so contract drift surfaces as test failures).
- It returns **`{"decision":"allow"|"deny","reason":...}`** based only on **`ALLOWED_USERNAMES`** (comma-separated env var): allow if `username` is in the list, otherwise deny.

**Why it exists**

Production PDP calls normally hit DOH’s control plane from the policy proxy flow. Customer-VPC tests can’t rely on that being reachable the same way, so **`policy_proxy_e2e_test`** deploys this stack (`PdpMockLambdaStack` / `pdp_mock` URL like `https://pdp-mock.<hosted_zone>/evaluate`) and points **`DOH_PDP_URL`** at it instead of real ABAC logic (which stays in `devopshero_app` and is tested elsewhere).

See the handler docstring:

```3:13:lambdas/pdp_mock/handler.py
Mock PDP used by the policy-proxy end-to-end test.

Replaces DOH's /api/pdp/evaluate with a deterministic "does this username appear
in ALLOWED_USERNAMES?" check so the test doesn't need the real DOH control
plane to be reachable from the customer VPC.

Triggered by ALB (ALB -> Lambda event shape). One route:
- POST /evaluate  body: {"app_id","oidc_sub","username","path"} -> {"decision","reason"}

Allow/deny is decided purely from the ALLOWED_USERNAMES env var (comma-separated).
Anything about the real ABAC engine lives in devopshero_app.services.abac and is
tested separately; this lambda intentionally stays trivial.
```

(Exact phase comment may differ slightly; the important bit is **`DOH_PDP_URL`** is set from **`ctx.pdp_mock_url`** before **`run_deployment`**.)

**Runtime consumer (indirect)**  
Nothing imports the Lambda package in Python. In the e2e scenario, the **running policy proxy** calls whatever URL is in **`DOH_PDP_URL`** (PDP **`/evaluate`** contract)—which the test wires to **`pdp_mock`**.

**Tests**  
Handler behavior is covered by **`lambdas/pdp_mock/tests/`** (the journal/conversations refer to eight such tests).

**Infra teardown**  
**`deploy_base.py`** mentions **`pdp-mock`** stacks so teardown/naming stays consistent with auth/proxy/other env-wide pieces—it’s naming/cleanup awareness, not “calling” the PDP.

So in one line: **`policy_proxy_e2e_test` deploys and points policy proxy deployments at **`pdp_mock`;** **`lambdas/pdp_mock`** tests validate the Lambda handler;** **`deploy_base`** acknowledges the **`pdp-mock`** stack in broader infra teardown.
