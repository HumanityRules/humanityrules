## Issues found

- **No reusable component** — The pill markup + color logic is copy-pasted across 4 templates for deployments/blueprints alone.
- **Inconsistent animation** — Only `_app_deployment_row.html` has the spinning icon, and only for `tearing_down`. Other in-progress statuses (`building`, `deploying`, `starting`, `pushing`) have no spinner anywhere.
- **Color mapping inconsistency** — `_app_card.html` sends `tearing_down`/`teardown_pending` to gray (the `else` branch); `workspaces.html` sends them to yellow (its `else` branch). These should both be yellow.
- **Label inconsistency** — Some places use `get_status_display` (model-defined human labels like "Building Image"), while `_app_card.html` and `workspaces.html` use `|title` filter (produces "Tearing_Down" not "Tearing Down").
- **Missing statuses** — `_app_card.html` doesn't handle `torn_down`, `tearing_down`, or `teardown_pending` explicitly.

---

## Recommendation

Create a single reusable partial (e.g., `partials/_status_pill.html`) that accepts a status value and a display label, maps it to the correct color and optional spinner, and is `{% include %}`-d everywhere. The color/animation mapping would live in one place. This would need to handle two "families" of status:

- **Deployment status** — `Deployment.Status` choices (pending, building, pushing, deploying, starting, succeeded, failed, rolled_back, torn_down, teardown_pending, tearing_down)
- **Blueprint status** — `DeploymentBlueprint.Status` choices (draft, deploying, failed, active, discarded)

Both share the same color semantics (green=success, yellow=in-progress, red=failure, blue=draft, gray=neutral) and the spinner should appear for **all** in-progress states, not just `tearing_down`.
