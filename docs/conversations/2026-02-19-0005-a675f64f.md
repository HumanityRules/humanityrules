## Context

The permissions editor's access level picker uses a native HTML `<select>` that closes after each selection, requiring repeated open-select-close cycles. The goal is to replace it with a custom dropdown with checkboxes that stays open for multi-selection — matching the behavior shown in the screenshot. Alpine.js is the standard companion to HTMX for this kind of local UI state management.

## Approach

Alpine.js manages **only** the open/close state of the dropdown (`x-data="{ open: false }"`). The checked/unchecked state of each level continues to come from the server via Django template variables. Each checkbox click fires an HTMX POST immediately. We switch all `hx-swap="innerHTML"` to `hx-swap="morph:innerHTML"` (idiomorph is already loaded) so Alpine's `open` state survives DOM updates and the dropdown stays open between toggles.

**No backend changes needed** — the existing `add_level`/`remove_level` actions and `access_levels` data structure with `{name, checked}` dicts already support this.

## How morph preserves Alpine state

When HTMX applies `morph:innerHTML`, idiomorph diffs old DOM vs new HTML. The Alpine wrapper `<div x-data="{ open: false }">` in the old DOM has `open = true` (user opened it). The new HTML has the same structure. Idiomorph patches only changed children (checkbox SVGs, chips), keeping the Alpine component alive with `open = true`. The dropdown stays visible.
