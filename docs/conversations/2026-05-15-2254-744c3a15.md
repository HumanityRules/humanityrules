Verified — `/goal` is a real built-in command (Claude Code v2.1.139+). Here's what it does:

## `/goal` — work until a condition holds

Sets a completion condition and Claude keeps running turns autonomously until that condition is met. After each turn, a small fast model (Haiku by default) evaluates whether the condition is satisfied; if not, Claude takes another turn instead of returning control to you. The goal clears automatically once met.

**Usage:**
- `/goal <condition>` — set a goal and start working immediately. The condition itself is the directive; no separate prompt needed.
- `/goal` — show status (condition, elapsed time, turns evaluated, tokens spent, evaluator's last reason).
- `/goal clear` — cancel an active goal early. Aliases: `stop`, `off`, `reset`, `none`, `cancel`. Running `/clear` also removes it.

**Example:**
```
/goal all tests in test/auth pass and the lint step is clean
```

**Writing good conditions:** the evaluator only sees what Claude surfaces in the conversation — it doesn't run commands itself. So phrase the condition so Claude's own output can prove it (e.g. "`npm test` exits 0", "`git status` is clean"). Add a bound like "or stop after 20 turns" to cap runtime. Max 4000 chars.

**vs. related features:**
- `/loop` — re-runs on a *time interval*; `/goal` re-runs *immediately after each turn* until a condition holds.
- Stop hook — same mechanism (`/goal` is a session-scoped wrapper around a prompt-based Stop hook), but persistent in settings.
- Auto mode — auto-approves tool calls within a turn; `/goal` removes the per-turn prompt. They compose well together.

**Other notes:** works in headless (`claude -p "/goal ..."`), desktop, and Remote Control. Survives `--resume`/`--continue` (counters reset). Disabled if the workspace isn't trusted or hooks are disabled.

Source: https://code.claude.com/docs/en/goal
