Add a new function that merges a statement by service (union of access_levels and resources):

```python
def upsert_statement(app_permission_request, service, access_levels, resources):
    """Merge access_levels and resources into the statement for `service`, creating it if absent."""
    statements = app_permission_request.statements or []
    existing = None
    for stmt in statements:
        if stmt.get("service") == service:
            existing = stmt
            break
    if existing is None:
        existing = {"service": service, "effect": "Allow", "access_levels": [], "resources": []}
        statements.append(existing)
    for level in access_levels:
        if level not in existing["access_levels"]:
            existing["access_levels"].append(level)
    for arn in resources:
        if arn not in existing["resources"]:
            existing["resources"].append(arn)
    app_permission_request.statements = statements
    app_permission_request.save(update_fields=["statements", "updated_at"])
```

## Assistant

When Python imports a package (like `devopshero_app.views`), it executes `__init__.py`. Your `__init__.py` does:

```python
from .security import security
```

This creates an attribute `security` on the `devopshero_app.views` module object, bound to the **function** `security`. It overwrites the attribute that would normally point to the **module** `devopshero_app.views.security`.

Here's the key: Python stores all imported modules in `sys.modules`. When you write `import devopshero_app.views.security`, Python does two things:

1. Loads the module and stores it in `sys.modules["devopshero_app.views.security"]` — this is the **module**
2. Sets `devopshero_app.views.security` as an attribute on the parent package — but your `__init__.py` already set that attribute to the **function**

The `as` alias in `import devopshero_app.views.security as security_views` resolves the dotted path by walking the attributes: it gets `devopshero_app`, then `.views`, then `.security` — and that last attribute lookup finds the **function**, not the module.

So every way of reaching `security` through the package namespace hits the function:
- `from . import security` → function
- `import devopshero_app.views.security as x` → function
- `from devopshero_app.views import security` → function

The module still exists in `sys.modules`, but the package attribute is shadowed. The only ways around it are ugly (`importlib.import_module`, `sys.modules` lookup).

The root cause is that `__init__.py` re-exports a function with the same name as the module. If the view function were named differently (e.g., `security_hub`), there'd be no conflict and `from . import security` would give you the module.

## Writing Guidelines

- **Be thorough** — Include enough detail to understand the context months later
- **Explain decisions** — Document what was decided and WHY, not just what changed
- **Capture learnings** — Document mistakes, corrections, and insights
- **Include technical details** — Specific configurations, error messages, solutions tried
- **No "Files Changed" sections** — Git tracks files; journal captures intent
- **Use current time** — Format: `YYYY-MM-DD HH:MM` (24-hour, local time)
