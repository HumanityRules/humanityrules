Everything looks clean. Here's a summary of the changes:

**New file: `_app_card_status.html`** — A partial template that wraps the status pill in a `<div id="app-status-{{ app.slug }}">`. When the latest deployment status is in-progress (`pending`, `building`, `pushing`, `deploying`, `starting`, `teardown_pending`, `tearing_down`), the div includes `hx-get` + `hx-trigger="load delay:10s"` + `hx-swap="outerHTML"` to poll the server every 10 seconds. Once the status reaches a terminal state, the server returns the same partial without polling attributes, and it stops automatically.

**New view: `app_card_status`** in `apps.py` — A lightweight GET endpoint that looks up the app and its latest deployment status in a single query, then renders just the status pill partial.

**Updated `_app_card.html`** — The inline status pill section was replaced with `{% include "_app_card_status.html" %}`.

**New URL:** `apps/<slug:app_slug>/card-status/` mapped to `app_card_status`.

The pattern follows the existing convention in the codebase (e.g., `_app_deployment_row.html` polls itself with `hx-trigger="load delay:3s"` during teardown). The self-replacing `outerHTML` swap means polling starts and stops automatically based on the current status.
