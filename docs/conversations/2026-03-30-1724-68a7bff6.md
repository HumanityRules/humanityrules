## My recommendation: Option B

Option B is the better choice because:

1. **It respects the existing layout.** The `grid-cols-2` `<dl>` was designed for short scalar values. Stuffing multi-line lists into it (Option A) creates a visual imbalance where the `<dt>` label floats at the top-left while a tall list stretches the right column.

2. **It separates concerns.** Scalar config (branch, CPU, memory) is conceptually different from list-style config (env vars, secrets). Giving them distinct visual sections makes the card easier to scan.

3. **It handles edge cases better.** With 0 vars, neither section renders. With 15+ vars, the list flows naturally at full width rather than being crammed into a half-width grid cell.

4. **Secret masking is more natural.** Having a dedicated "Secrets" sub-section with masked values clearly signals "these are sensitive" without cluttering the main property grid.

The only design detail to decide: whether to truncate long env var values (e.g., `truncate` filter or `max-w-[200px] truncate` on the value span) to prevent very long values from blowing out the layout.
