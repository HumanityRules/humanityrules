## Diagnosis Report: SSE `net::ERR_HTTP2_PROTOCOL_ERROR` in Production

### Symptoms
- Browser console shows 2,047+ errors: `GET .../stream/ net::ERR_HTTP2_PROTOCOL_ERROR 200 (OK)`
- htmx-ext-sse reconnects continuously, creating an error loop
- ECS logs show `CancelledError` exceptions as connections close

### Root Cause

**HTTP/2 + SSE Protocol Mismatch with CloudFront Timeouts**

The architecture is:

```
Browser ──HTTP/2──> CloudFront ──HTTPS──> ALB ──HTTP──> ECS
```

The issue has two compounding factors:

1. **CloudFront uses HTTP/2** (configured in `cdn_stack.py` line 160: `http_version=cloudfront.HttpVersion.HTTP2_AND_3`)

2. **CloudFront's default origin response timeout is 30 seconds** — when the SSE stream is idle (waiting for user input or agent processing), CloudFront interprets the lack of data as a timeout and resets the HTTP/2 stream.

3. **No heartbeat/keepalive in SSE stream** — looking at `agent_runner.py` lines 176-178, when there's no pending message, the runner does `await asyncio.sleep(0.5)` but **sends nothing to the client**:

```python
else:
    # No pending message - wait before checking again
    await asyncio.sleep(0.5)
```

The SSE connection stays open but silent, triggering CloudFront's idle timeout.

4. **HTTP/2 stream reset manifests as `ERR_HTTP2_PROTOCOL_ERROR`** — when CloudFront closes the connection mid-stream due to timeout, the HTTP/2 RST_STREAM frame causes this Chrome error. The 200 status appears because the connection initially succeeded.

5. **htmx-ext-sse auto-reconnects** — each reconnect creates a new SSE connection that immediately starts the same timeout cycle, causing thousands of errors.

### Why This Happens in Production but Not Locally

Locally, you're likely connecting directly to the Django dev server (HTTP/1.1) without CloudFront in the path. The ALB alone has a 60-second idle timeout, and HTTP/1.1 doesn't exhibit this particular error pattern.

### Recommended Fixes

**Short-term (fixes the immediate issue):**

1. **Add SSE heartbeat comments** — Modify `chat_stream` to send periodic `:keepalive\n\n` SSE comments (which are ignored by clients but keep the connection alive):

```python
# In agent_runner.py, during idle polling
yield ":keepalive\n\n"  # SSE comment, keeps connection alive
```

**Medium-term (more robust):**

2. **Increase CloudFront origin response timeout** — In `cdn_stack.py`, configure the ALB origin with a longer timeout:

```python
alb_origin = origins.LoadBalancerV2Origin(
    alb,
    protocol_policy=cloudfront.OriginProtocolPolicy.HTTPS_ONLY,
    read_timeout=Duration.seconds(60),  # or higher
)
```

**Long-term considerations:**

3. **Consider HTTP/1.1 for SSE endpoints** — CloudFront doesn't support per-behavior HTTP versions, but if SSE issues persist, you might need a separate origin behavior with different configuration or bypass CloudFront for SSE.

### Summary

The SSE stream goes idle while waiting for user/agent activity. CloudFront's 30-second origin response timeout fires, resetting the HTTP/2 stream. This manifests as `ERR_HTTP2_PROTOCOL_ERROR` in Chrome. The fix is to send periodic heartbeat comments to keep the stream active.

## Assistant

Yes, SSE works fine over HTTP/2 end-to-end. The protocol isn't the fundamental issue here.

**HTTP/2 + SSE compatibility:**
- HTTP/2 multiplexes streams over a single connection — SSE just becomes one of those streams
- The `text/event-stream` content type and event format work identically
- Many production systems (including ChatGPT, Claude.ai) use SSE over HTTP/2

**The real issue is idle timeouts**, not protocol incompatibility:
- CloudFront's origin response timeout (default 30s) closes streams that go silent
- HTTP/2 makes the closure more visible — a `RST_STREAM` frame triggers `ERR_HTTP2_PROTOCOL_ERROR` in Chrome
- HTTP/1.1 would exhibit similar behavior but with a less alarming error message (connection reset)

**The heartbeat fix is still the right answer** regardless of HTTP version. Sending periodic `:keepalive\n\n` comments keeps data flowing, preventing timeout-based disconnections at any layer (CloudFront, ALB, or any proxy in between).

    async def event_generator():
        """Subscribe to agent runner's event queue and yield SSE events."""
        logger.info(f"SSE event_generator started for conversation {conversation_id}")

        try:
            # Get or spawn agent runner
            runner = await agent_runner.ensure_agent_running(conversation=conversation)
            agent_runner.mark_client_connected(conversation_id=conversation_id)

            # Consume events from runner's queue with keepalive
            # Keepalive interval must be shorter than CloudFront origin timeout (30s default)
            keepalive_interval = 15.0
            while True:
                try:
                    event = await asyncio.wait_for(runner.event_queue.get(), timeout=keepalive_interval)
                    if event is None:
                        # Sentinel: runner finished, exit loop
                        logger.info(f"Agent runner completed for conversation {conversation_id}")
                        break
                    yield _format_sse_event(event=event)
                except asyncio.TimeoutError:
                    # No event within timeout - send SSE comment to keep connection alive
                    yield ": keepalive\n\n"
