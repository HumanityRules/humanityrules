Now I have the full picture. Here's why the agent mentions Nixpacks:

**The source is the `deploy_app` tool schema.** The MCP tool definition in `mcp_tools.py` explicitly lists it as an option:

```570:570:devopshero_app/services/agent/mcp_tools.py
            "build_strategy": {"type": "string", "description": "How to build: dockerfile, nixpacks, or buildpack"},
```

When the LLM sees the tool schema, it naturally surfaces all three options to the user — `dockerfile`, `nixpacks`, and `buildpack` — because the schema tells it those are valid choices.

**This contradicts the design intent.** Your own deployment agent design doc says:

```212:212:docs/deployment_agent_design.md
**Build:** Always containerize. User never chooses Nixpacks vs Docker.
```

And yet, nothing in the system prompt (`system_prompt_app_deployment.md`) tells the agent to default to `dockerfile` or to avoid mentioning build strategy alternatives. The system prompt has guidance on container sizes, database defaults, and question philosophy, but zero guidance on build strategy.

**The chain that causes this:**

1. `deploy_app` tool schema says `build_strategy` accepts `"dockerfile, nixpacks, or buildpack"`
2. `build_strategy` is in the `required` list — the agent *must* choose one
3. The repo analyzer doesn't output a build strategy recommendation
4. No system prompt guidance says "always pick dockerfile" or "don't mention this to the user"
5. So the LLM, being helpful, asks the user which build strategy they want

**Possible fixes:**

- **Simplest** — Add a line to `<infrastructure_decisions>` in the system prompt: *"Build strategy: always use `dockerfile`. Do not mention nixpacks or buildpack to the user."*
- **Cleaner** — Remove `nixpacks` and `buildpack` from the tool description and schema entirely if DOH doesn't actually support them yet, and hard-default `build_strategy` to `"dockerfile"` in the tool handler
- **Middle ground** — Keep the enum in the model for future use, but change the tool description to just say `"Build strategy (always use 'dockerfile')"` and move `build_strategy` out of the `required` list, defaulting it server-side
