## Proposed Solutions

### Option A: Quick Fix — Update default to a modern, available version (Recommended)

Change the default version to `16.4` (same as control plane) and expand the version map:

```python
AURORA_POSTGRES_DEFAULT_VERSION = "16.4"

AURORA_POSTGRES_VERSION_MAP = {
    "15.7": rds.AuroraPostgresEngineVersion.VER_15_7,
    "15.8": rds.AuroraPostgresEngineVersion.VER_15_8,
    "16.4": rds.AuroraPostgresEngineVersion.VER_16_4,
    "16.6": rds.AuroraPostgresEngineVersion.VER_16_6,
    "17.2": rds.AuroraPostgresEngineVersion.VER_17_2,
}
```

**Pros**: Simple, matches control plane, low risk
**Cons**: Hardcoded versions will need periodic updates

### Option B: Use CDK's `of()` method for dynamic versions

Allow users to specify any version and use `AuroraPostgresEngineVersion.of()`:

```python
def get_engine_version(engine_config: appconfig.EngineConfig) -> "rds.IClusterEngine":
    if engine_config.family == "aurora-postgresql":
        version_key = engine_config.version or "16.4"  # sensible default
        # Try predefined map first, fallback to dynamic
        version = AURORA_POSTGRES_VERSION_MAP.get(version_key)
        if not version:
            # Use dynamic version creation
            version = rds.AuroraPostgresEngineVersion.of(
                aurora_postgres_full_version=version_key,
                aurora_postgres_major_version=version_key.split('.')[0],
            )
        return rds.DatabaseClusterEngine.aurora_postgres(version=version)
```

**Pros**: More flexible, future-proof
**Cons**: More complex, version strings need to be valid Aurora versions

### Option C: Remove version pinning entirely — let AWS choose

Use the latest Aurora PostgreSQL version automatically:

```python
def get_engine_version(engine_config: appconfig.EngineConfig) -> "rds.IClusterEngine":
    if engine_config.family == "aurora-postgresql":
        # Use default (latest) Aurora PostgreSQL
        return rds.DatabaseClusterEngine.AURORA_POSTGRESQL
```

**Pros**: Always works, no maintenance
**Cons**: Less control, behavior changes over time

## Assistant

The version map exists to translate user-friendly version strings (like `"15.4"`) into CDK constants (like `rds.AuroraPostgresEngineVersion.VER_15_4`). It was designed to:

1. **Validate versions** — Only allow versions explicitly listed in the map
2. **Support user choice** — Let users specify `engine_version` on the `Datastore` model

However, looking at the current implementation, **the map only has one entry** (`15.4`), so it's not really providing any choice. And the `Datastore.engine_version` field is optional — if blank, it uses the default.

**Simpler approach**: Just pick a sensible default and use CDK's `of()` for any explicit user-specified version. The map becomes unnecessary:

```python
AURORA_POSTGRES_DEFAULT_VERSION = "16.4"

def get_engine_version(engine_config: appconfig.EngineConfig) -> "rds.IClusterEngine":
    if engine_config.family == "aurora-postgresql":
        v = engine_config.version or AURORA_POSTGRES_DEFAULT_VERSION
        major = v.split('.')[0]
        version = rds.AuroraPostgresEngineVersion.of(
            aurora_postgres_full_version=v,
            aurora_postgres_major_version=major,
        )
        return rds.DatabaseClusterEngine.aurora_postgres(version=version)
```

This way:
- Default is `16.4` (matches your working control plane)
- If a user explicitly specifies a version, it passes through to AWS (which will validate it)
- No map to maintain
