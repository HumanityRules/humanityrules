## Diagnosis

The problem is clear. The OpenClaw gateway validates the browser's `Origin` header against an allowlist, and the current `openclaw.json` does **not** include `allowedOrigins` in the `controlUi` section. By default, OpenClaw only allows connections from `localhost`/`127.0.0.1`, so when the browser connects from `https://ai-assistant-openclaw.chsandbox.com`, the origin check fails.

Here's the relevant config that's missing the key setting:

```15:19:/Users/vmendi/websites/deployable-repos/openclaw_agent/openclaw.json
    "controlUi": {
      "dangerouslyDisableDeviceAuth": true,
      "allowInsecureAuth": true
    },
```

## Solutions (pick one)

**Option A — Explicit origin (recommended).** Add the exact domain to `allowedOrigins`:

```json
"controlUi": {
  "dangerouslyDisableDeviceAuth": true,
  "allowInsecureAuth": true,
  "allowedOrigins": ["https://ai-assistant-openclaw.chsandbox.com"]
}
```

This is the most secure approach. The origin must include the exact scheme (`https://`) and hostname, with no trailing slash or port (443 is implicit for HTTPS).

**Option B — Host header fallback.** If the domain might change (e.g., DOH assigns it dynamically), use the fallback mode instead:

```json
"controlUi": {
  "dangerouslyDisableDeviceAuth": true,
  "allowInsecureAuth": true,
  "dangerouslyAllowHostHeaderOriginFallback": true
}
```

This tells OpenClaw to trust the `Host` header as a valid origin. Since the app sits behind DOH's ALB (which controls the Host header), this is reasonably safe for this deployment pattern.

**Option C — Wildcard (least secure).** Allow any origin:

```json
"controlUi": {
  "dangerouslyDisableDeviceAuth": true,
  "allowInsecureAuth": true,
  "allowedOrigins": ["*"]
}
```

Works but disables origin validation entirely.

## My recommendation

For a DOH deployment, **Option A** is best since you know the domain upfront. If you want me to apply the fix, just say which option and I'll update `openclaw.json`, commit, and you can redeploy.

**Note:** There's a [known OpenClaw bug](https://github.com/openclaw/openclaw/issues/49950) where CLI commands that touch `openclaw.json` can reset `allowedOrigins` to defaults. Since this deployment bakes the config into the Docker image (not modified at runtime by CLI), that bug shouldn't affect you.
