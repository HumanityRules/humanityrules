## Step 3: Policy Evaluation Service

**New file: `devopshero_app/services/abac.py`**

Action catalog and hierarchy:
```
workspace:admin implies workspace:view, workspace:edit
environment:admin implies environment:view, environment:deploy, environment:approve
```

Key functions:

- **`get_effective_attributes(organization, user)`** — returns list of `(key, value, source)` tuples where source is "system", "direct", or "group:GroupName". System always includes `("authenticated", "true", "system")`. Queries `IdentityAttribute` for direct, `GroupMembership` + `GroupAttribute` for group-inherited.

- **`get_effective_tags(resource, resource_type)`** — returns list of `(key, value, source)` tuples. For apps: direct tags + inherited workspace tags (source="inherited:WorkspaceName"). For workspaces/environments: all direct.

- **`evaluate_policies(organization, user, resource, resource_type)`** — core engine. Returns `set[str]` of allowed actions. Algorithm:
  1. Load all org policies for the resource_type
  2. Compute effective attributes (as `set[tuple[key, value]]`)
  3. Compute effective tags (as `set[tuple[key, value]]`)
  4. For each policy: check identity condition match (all AND-ed pairs present in attributes, or wildcard `*`) AND resource condition match (all AND-ed pairs present in tags, or wildcard `*`)
  5. Collect grants and denials from matching policies
  6. Expand grant hierarchy (`workspace:admin` -> also add `workspace:view`, `workspace:edit`)
  7. Remove any action that appears in deny set (deny-overrides)
  8. Return final grant set

- **`check_action(organization, user, resource, resource_type, action)`** — convenience, calls evaluate_policies, returns bool

- **`evaluate_policies_unscoped(organization, user, resource_type)`** — evaluates with empty tag set (only wildcard-resource policies match). Used for "can user create new workspaces?" checks.

- **`filter_permitted_resources(organization, user, queryset, resource_type, action)`** — given a queryset of resources, return only those the user has `action` on. Loads all matching policies once, then evaluates per-resource. Used for list views.

- **`is_org_admin(organization, user)`** — checks if user has `org-role=admin` attribute (direct or group-inherited). Used for settings pages.

- **`bootstrap_organization(organization, admin_user)`** — creates seed data (see Step 4).

- **`create_default_app_policy(app)`** — creates default `app:use` policy for new apps (see Step 5).
