## Current state

`devopshero_app/services/jobs/app_remove_executor.py:103-111` calls `secrets_utils.delete_secrets_matching_prefix(..., force_immediate=False)`, which in `secrets_utils.py:380-386` translates to `DeleteSecret(RecoveryWindowInDays=7)`.

AWS behavior: with a recovery window, the secret name is reserved for the full window (min 7 days). Trying to create a secret with the same name returns `InvalidRequestException: You can't create this secret because a secret with this name is already scheduled for deletion.` This blocks redeploy-with-same-name for 7 days unless you manually call `RestoreSecret` + `DeleteSecret(ForceDeleteWithoutRecovery=true)`.

## The ask, as I understand it

When "Remove App" deletes secrets, do a hard purge (`ForceDeleteWithoutRecovery=true`) so the user can immediately redeploy the app with the same secret names.

## Proposal

Flip the call site at `app_remove_executor.py:110` from `force_immediate=False` to `force_immediate=True`. That's it — the plumbing already exists in `secrets_utils.py`.

## Tradeoff worth naming

`ForceDeleteWithoutRecovery` is **irreversible and immediate** — no undo if the removal was a mistake. Today, the 7-day window is effectively the user's safety net. Three ways to handle that:

1. **Always force-delete** (simplest, matches your ask literally). Relies on the "Remove App" confirmation UX being the sole safety net.
2. **Add an `AppRemovalJob.purge_secrets` flag** alongside the existing `delete_secrets` / `delete_efs_data` / `delete_policies` flags — user opts in per-removal. Consistent with the existing pattern (these are already separate toggles).
3. **Always force-delete, but only when `delete_secrets=True`** — treat "delete secrets" as implying "purge." Simpler than #2, still gated on the existing flag.

My recommendation is **#3**: the user already had to explicitly opt into `delete_secrets`, so inheriting the purge semantics from that flag keeps the UI simple and matches the "I want to redeploy cleanly" intent. #2 adds a toggle most users won't understand.
