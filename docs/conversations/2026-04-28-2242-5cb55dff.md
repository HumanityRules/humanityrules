1. **Surgical in-place rewrite** — sed just the `terminal.backend:` line on every boot, leave the rest alone. Cheap, but you're now maintaining two code paths (template render + in-place patch) for the same field.
2. **Split config** — move DOH-managed knobs (backend, tool_image, volumes) into a separate file that's always regenerated, and have hermes merge it with the user's config. Clean, but requires upstream support or a patch.
3. **Regenerate only if env changed** — stash a hash of the templated inputs and rewrite when it drifts. Solves the drift problem generically but adds state.

None of these are free — they all trade the current "user config is sacred" invariant for "DOH can push certain fields." Worth doing if you expect to toggle backend-type settings often; overkill if this is a one-off test.
