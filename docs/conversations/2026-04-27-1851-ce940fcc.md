## Why bash is missing

The DinD image is built on `docker:26.1.0-dind`, which is Alpine-based. Our `Dockerfile` only adds `python3 py3-psutil zstd` — no `bash`. So the only shell available is busybox `/bin/sh` (ash):

```1:13:template_repos/doh_dind/Dockerfile
FROM docker:26.1.0-dind

# Alpine-based; we need python3 for the snapshotter and zstd for the compressed
# tarball pipeline. py3-psutil isn't strictly required (our snapshotter uses
# the docker CLI, not the daemon socket directly), but keeping it in case we
# want in-process resource reporting later without a second image bump.
RUN apk add --no-cache python3 py3-psutil zstd

COPY --chmod=755 entrypoint.sh /entrypoint.sh
COPY --chmod=755 snapshotter.py /usr/local/bin/snapshotter.py

ENTRYPOINT ["/entrypoint.sh"]
```

Our own runtime doesn't need bash — `entrypoint.sh` is `#!/bin/sh` and `snapshotter.py` is Python. Bash is only missing from the perspective of operator tools attaching via ECS Exec.

## What the two commands actually need

**`doh_app_shell`** — soft requirement. Defaults to `--command /bin/bash`:

```196:198:devopshero_app/management/commands/doh_app_shell.py
            "--command",
            default="/bin/bash",
            help="Executable to run inside the container (default: /bin/bash)",
```

Workaround today: `--command /bin/sh`. So bash is convenience here, not strictly required.

**`doh_app_exec`** — hard requirement. The SSM command itself is bash, and the inner script is invoked via bash:

```45:50:devopshero_app/management/commands/doh_app_exec.py
    inner = f"{env_exports}{cwd_cmd}bash /tmp/doh_exec_script.sh"
    if timeout is not None:
        inner = f"timeout --preserve-status {int(timeout)}s {inner}"
    if run_as is not None:
        # -H so ~ resolves to the target user's home (config loaders depend on it).
        inner = f"sudo -EH -u {_sh_quote(run_as)} bash -c {_sh_quote(inner)}"
```

```150:150:devopshero_app/management/commands/doh_app_exec.py
        "--command", f"bash -c {_sh_quote(wrapper_script)}",
```

So `doh_app_exec` against the DinD container fails today with `bash: not found`, regardless of flags. There's no shell flag to override that to `sh`. Installing bash is the only way to make it work without rewriting the wrapper.

## Other tools `doh_app_exec` invokes

The wrapper uses: `echo`, `base64 -d`, `chmod`, `mktemp -u`, `mkfifo`, `sed`, `wait`, `rm`, `timeout`, `sudo`. Of these:

- **Busybox-compatible (already on the image):** `echo`, `base64 -d`, `chmod`, `mktemp -u`, `mkfifo`, `sed`, `wait`, `rm`. All fine.
- **`timeout --preserve-status`** — only GNU `coreutils` supports `--preserve-status`; busybox `timeout` does not. So `--timeout N` would fail. Without `--timeout`, no `timeout` invocation happens at all.
- **`sudo`** — not on Alpine by default. But our DinD container has no `user:` field in its task definition (`_DOCKER_DIND_CONTAINER` in `seed_app_templates.py` doesn't set one), so it runs as root. `_task_container_user` returns `None`, `run_as` becomes `None`, and the wrapper never wraps with `sudo`. Only matters if an operator passes `--as someuser` — which there's no realistic reason to do for DinD.

## Recommendation

**Yes — add `bash`.** The change is one word in the Dockerfile:

```Dockerfile
RUN apk add --no-cache bash python3 py3-psutil zstd
```

Then bump `DOH_DIND_IMAGE_VERSION` from `0.1.1` → `0.1.2` in `devopshero_app/management/commands/seed_app_templates.py`, build, push:

```bash
uv run manage.py doh_build_prebuilt_image --source-dir template_repos/doh_dind --ecr-repo doh-dind --tag 0.1.2
```

**Cost / risk:**

- **Size:** bash is ~1.7 MB compressed in apk, ~5 MB extracted. The base `docker:dind` image is already several hundred MB; this is noise.
- **Snapshot impact:** zero. The snapshotter only captures the `hermes-*` tool container's writable layer (`docker export`). The DinD image's own layers are never snapshotted.
- **Side effects on existing scripts:** none. `apk add bash` doesn't change `/bin/sh` — that stays a busybox symlink to `ash`. Our `entrypoint.sh` keeps running under ash exactly as before. Bash just shows up at `/bin/bash` for operator use.
- **What still won't work:** `doh_app_exec --timeout N` against DinD. The fix would be `apk add coreutils` (~5 MB) or — cleaner — patch `_build_wrapper_script` to use a portable timeout. Not urgent; you can decide if/when the need shows up.
- **What you don't need:** `sudo`. DinD runs as root in the task definition, so `--as` doesn't engage the sudo wrap.

**One caveat I'd flag separately:** running `doh_app_exec` against the DinD container is a slightly weird operation in the first place — the container's purpose is to run `dockerd` plus our snapshotter as PID 1, not host arbitrary scripts. Most introspection you'd want is "what containers is dockerd seeing" / "what's in `/var/lib/doh-dind/persistence`", which is fine over a shell or an exec, but you'll be poking at a privileged sidecar. Worth keeping in mind, not a reason to block the change.
