## Gotchas

- `curl https://raw.githubusercontent.com/…` may fail with exit 35 on this machine. Default to `gh api … | base64 -d`.
- `gh api` with unquoted `?ref=…` queries trips zsh glob matching — always single-quote the path.
- Patch anchors include line numbers; don't trust them. Always grep for the *identifier* being changed, not the line number in the patch header.
- "Landed" ≠ "same code." Upstream may refactor to a different shape (helper function, different condition). Read the upstream code and confirm the semantics cover our case before declaring the patch obsolete.
- Our patches apply with `patch -p1 -N` (idempotent). A patch that's "landed verbatim" becomes a no-op and is safe to leave, but carrying dead patches masks drift — prefer removing.

## Root cause

The WebUI builds the dropdown by walking `detected_providers` and, for each, looking up model lists from:
1. a hardcoded `_PROVIDER_MODELS` table (`api/config.py:612`), **or**
2. `config.yaml`'s `providers.<pid>.models` section (`api/config.py:1685-1694`).

For **bedrock**, the WebUI's `_PROVIDER_MODELS` has **no entry** (`api/config.py:612-758` — anthropic, openai, openai-codex, google, deepseek, nous, zai, kimi-coding, minimax, copilot, opencode-zen, opencode-go, gemini, mistralai, qwen, x-ai — no bedrock). And our `config.yaml.template` ships `providers: {}` (line 13).

So the flow is:
- `list_available_providers()` → bedrock comes back as `authenticated: True` (IAM creds via IMDS/task role resolve through `has_aws_credentials()` in `agent/bedrock_adapter.py:152`), so `detected_providers` includes `"bedrock"`.
- Group builder at `api/config.py:1685`: `pid in _PROVIDER_MODELS` is False, `pid in cfg.get("providers", {})` is False → falls to the `else` branch, which only appends a group if `auto_detected_models` is non-empty; but `bedrock-runtime.<region>.amazonaws.com/v1/models` doesn't exist, so `auto_detected_models` is empty → **no bedrock group is ever added**.
- The agent is unaffected because it reads `model.provider: bedrock` from `config.yaml` directly — that's why the session still routes to Bedrock+Opus 4.7.

The WebUI *does* know about the `bedrock` provider in `_PROVIDER_ALIASES` (line 578-581), but that alias table isn't what feeds the dropdown.

Why GPT-5.4 ends up selected: most likely your container also has `OPENAI_API_KEY` set (or OpenAI creds in the hermes credential store), so `openai` is in `detected_providers`, its hardcoded `_PROVIDER_MODELS["openai"]` list fills the dropdown, and the first entry (GPT-5.4) wins the UI default.

## The fix

Populate `config.yaml`'s `providers.bedrock.models` from `entrypoint.sh` when `DOH_LLM_PROVIDER=bedrock`. Upstream's `hermes_cli.models` does have a Bedrock discovery path (`curated_models_for_provider` → `provider_model_ids("bedrock")` → `discover_bedrock_models` at `hermes_cli/models.py:2625-2629`), but the WebUI doesn't call it — it only uses `provider_model_ids` for `ollama-cloud`. So we feed the WebUI what it wants.

Rough shape: replace `providers: {}` in the template with a placeholder and render it:

```yaml
providers:
  bedrock:
    models:
      - us.anthropic.claude-opus-4-7
      - us.anthropic.claude-sonnet-4-5-20250929-v1:0
      - us.anthropic.claude-haiku-4-5-20251001-v1:0
```

Two implementation options:

**A. Static list in entrypoint.sh.** Simple, no boto3 dependency at boot, but we hand-maintain the model IDs.

**B. Discover at boot via boto3.** Shell-spawns a tiny Python snippet that calls `agent.bedrock_adapter.discover_bedrock_models(region)` and writes YAML. Always in sync with what the account has enabled, at the cost of an extra control-plane call and requiring `bedrock:ListFoundationModels`/`ListInferenceProfiles` on the task role.

I'd recommend **A** for now — a 3-item curated list keeps boot fast and matches what we actually want customers selecting. We can revisit B if/when we start varying model enablement per account.

Want me to proceed with A? If so, do you want the list to include both the inference-profile IDs (`us.anthropic.claude-opus-4-7`) and the Converse-only non-Claude models (Nova, Llama), or Claude-only?
