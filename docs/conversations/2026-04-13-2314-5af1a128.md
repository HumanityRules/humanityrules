## Diagnosis: OpenClaw Deployment Failure

### What happened

The container starts and runs fine. The deployment **timed out at 180s** waiting for ECS `rolloutState=COMPLETED`, because ECS kept cycling tasks that failed ALB health checks during their startup window.

The service **did eventually stabilize** — right now the deployment shows `rolloutState: COMPLETED` with 1/1 healthy task. But it took longer than the 180s DOH timeout.

### Timeline

- **03:28:01** — DOH triggers `forceNewDeployment=True`, starts 180s timer
- **03:29:09** — Task `15b66d6e` starts. OpenClaw HTTP server up by 03:29:14 (~5s)
- **03:29:15** — Gateway reports "ready" with 6 plugins
- **03:29:58** — Model warmup fails: `Unknown model: openai/claude-sonnet-4-20250514`
- **03:30:05** — Last plugin (acpx runtime) finishes loading (~56s after container start)
- **03:30:13** — ECS starts replacement Task `4e1942e7` (ALB had marked the first task unhealthy during its ~60s initialization)
- **03:31:03** — Task `4e1942e7` receives SIGTERM

- **03:42:41** — ECS starts yet another replacement `cca6394a`, also killed at 03:44:42
- Eventually the first task passed health checks, cycling stopped, deployment completed

### Root cause: health check timing mismatch

OpenClaw's own health monitor has a **60-second startup grace period**:

```
[health-monitor] started (interval: 300s, startup-grace: 60s, channel-connect-grace: 120s)
```

During this grace period, `/health` likely returns non-200. But the DOH health check configuration (in DEBUG mode) is aggressive:

- **`health_check_grace_period`: 0 seconds** — ECS evaluates health immediately
- **ALB interval**: 5s, **unhealthy threshold**: 3 = task marked unhealthy in ~15s
- **ALB healthy threshold**: 2 = needs ~10s of successes to recover

So the sequence is: task starts → `/health` returns non-200 for ~60s → ALB marks unhealthy at ~15s → ECS starts cycling replacements → each replacement has the same 60s startup → cycling continues beyond the 180s timeout.

The surviving task (`15b66d6e`) eventually passed health checks once the startup grace elapsed, but by then DOH had already given up.

### Secondary issue: wrong model provider prefix

The template sets `OPENCLAW_DEFAULT_MODEL=claude-sonnet-4-20250514`. OpenClaw doesn't recognize the bare model name and falls back to `openai/claude-sonnet-4-20250514`, which fails:

```
[gateway] startup model warmup failed for openai/claude-sonnet-4-20250514: Error: Unknown model: openai/claude-sonnet-4-20250514
```

```
Embedded agent failed before reply: Unknown model: openai/claude-sonnet-4-20250514
```

It should be `anthropic/claude-sonnet-4-20250514` so OpenClaw routes to the Anthropic provider.

### What to fix

- **Health check grace period** — The 0s grace in DEBUG mode doesn't work for slow-starting apps. OpenClaw needs at least 60-90s before health checks start counting.
- **DOH stabilization timeout** — 180s is too tight for apps that take 60+ seconds to become healthy plus ECS cycling time. 300-360s would be safer.
- **Model config** — Change the default from `claude-sonnet-4-20250514` to `anthropic/claude-sonnet-4-20250514` in both the template seed and the `.env.example`.
