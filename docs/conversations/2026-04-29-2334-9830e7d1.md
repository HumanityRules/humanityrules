Yes for *intent* (operators want a single, obvious entry point), but there's a hard runtime constraint that prevents the literal version of that.

## The constraint

`prod_manage.sh` works by `aws ecs execute-command`'ing into the **prod app container** and running `manage.py …` there. That container is the Django app — **no Docker daemon, not privileged, not a builder**. `docker build` inside it would just fail. So `./prod_manage.sh doh_build_prebuilt_image …` literally can't do the build, even if we wired it up.

## So operator actions split into two flavors

- **Prod-compute, prod-DB:** anything that's just DB reads/writes or pure boto3 calls. Today's `prod_manage.sh` covers these perfectly. (`doh_query`, `doh_control teardown-env`, `seed_app_templates`, `doh_secrets`, etc.)
- **Laptop-compute, prod-DB:** needs the operator's local machine — Docker daemon for `docker build`, interactive stdin for shells, sometimes large local source trees. Has to run on the laptop, but wants prod's DB as the source of truth for "where to assume into" + "what slug names the env."

The doh-dind build sits in the second bucket, and it's not alone — `doh_efs_browse` (interactive shell), `doh_app_shell`/`doh_app_exec`, future builds for `policy_proxy`/`learneo-mcp` all live there too.

## The right shape, IMO: keep `prod_manage.sh` as the single front door, make it smart

Don't ask the operator to pick a script. Have `prod_manage.sh` itself know which commands need to run locally, and route them transparently:

```
prod_manage.sh <cmd> [args]
  ├── if cmd ∈ LOCAL_EXEC_COMMANDS:
  │     1. ECS-exec a doh_query to resolve the target (account_id, external_id, region, slug) from prod's DB
  │     2. Run `uv run manage.py <cmd>` LOCALLY, with the resolved values injected as --aws-account-id/--aws-external-id/--aws-region/--env-slug
  │
  └── else (default):
        ECS-exec `manage.py <cmd>` inside the prod task   (today's behavior)
```

So as the operator, you uniformly type:

```bash
./prod_manage.sh doh_build_prebuilt_image \
    --account "Course Hero Sandbox" \
    --env production \
    --source-dir template_repos/doh_dind \
    --ecr-repo doh-dind \
```

…and the script figures out "this one builds Docker, so run it on the laptop with prod-resolved target."
