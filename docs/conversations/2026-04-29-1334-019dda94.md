## Assistant

The main thing we lose is a **legacy fallback display signal**, not model behavior.

That code appears intended to do two things:

1. **Subagent delegation progress:** take the first line of a child agent’s output and show it as parent-side progress.
   We kept this.

2. **Post-hoc “reasoning available” fallback:** when no structured reasoning stream exists, take `assistant_message.content`, strip any `<think>`-style tags, and emit it as `reasoning.available`.
   We removed this for top-level agents.

The consequence is:

- For providers that emit real reasoning tokens, nothing should be lost. Those still flow through the structured reasoning callbacks.
- For providers that do **not** emit real reasoning tokens, the WebUI should stop showing a fake thinking bubble containing the final answer.
- For any model that embeds actual reasoning inline in `assistant_message.content` using `<think>`/`<reasoning>` tags instead of a structured stream, this patch means the WebUI will no longer promote that inline content into a thinking bubble. But the old code did not reliably detect “only thinking”; it treated the whole final answer as thinking whenever content existed.

So the tradeoff is: we lose a questionable fallback that could maybe surface inline scratchpad-style reasoning for some models, but we eliminate a clear false-positive path that mislabels final answer text as thinking.

This does not affect the model call, tool execution, final response rendering, or Bedrock streaming itself. It only changes what Hermes reports to the UI as `reasoning.available`.
