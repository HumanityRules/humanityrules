Here's what I'd propose — but first, one important constraint I want to flag from reading the file:

**The EFS constraint:** `hermes-agent/` gets copied from `/opt/hermes-defaults/` to `$HERMES_DIR` only on first boot (line 70). The patches then run on **every** boot against the EFS copy. That's load-bearing — it lets a new image ship updated patches that apply to already-deployed EFS volumes. So build-time-only patching (tempting, but clean) would silently stop fixing existing deployments.

**Proposed structure** (keeps runtime patching, but gets it out of the shell script):

```
template_repos/hermes_agent/patches/
├── 01-run_agent-bedrock-dots.patch        # unified diff
├── 02-run_agent-bedrock-caching.patch     # unified diff
├── 03-auxiliary_client-wire-bedrock.patch # small diff: imports + 2 hook points
├── overlay/
│   └── agent/bedrock_aux_client.py        # the ~70-line Bedrock wrapper, as a real module
└── apply.py                               # orchestrator: copy overlay, `patch -N --forward` each diff
```

Dockerfile COPYs `patches/` into `/opt/hermes-defaults/patches/`. entrypoint.sh collapses to one line:

```bash
python3 /opt/hermes-defaults/patches/apply.py "$HERMES_DIR/hermes-agent"
```

**What this buys you:**
- Each patch is a reviewable unified diff, not a Python heredoc inside a shell heredoc
- The BedrockAuxiliaryClient class becomes a real `.py` file — syntax-highlighted, lintable, testable, diffable
- Idempotency is standard (`patch -N --dry-run` → skip if already applied, no custom "is this already patched?" string search)
- Easy CI guard: run `apply.py` against a clean hermes-agent checkout in a test, catch upstream drift before release

**Main tradeoff:** unified diffs match on surrounding context lines, so they're slightly more brittle to upstream whitespace/refactors than anchor-based string replacement. You could mitigate with generous context (`git diff -U10`) or, if you want maximum resilience, keep Part 3's `aws_sdk` handler as a Python AST rewrite instead of a diff. I'd start with pure `.patch` files and only escalate if upstream actually churns.
