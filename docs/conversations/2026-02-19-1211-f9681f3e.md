# Fragment-level HTMX swaps for permissions editor

## Context

The permissions editor currently replaces the **entire service group** (`morph:outerHTML` on `#service-group-{service}`) for every mutation — adding a resource, removing a resource, toggling an access level. This causes two problems:

1. **Alpine state corruption**: morphing destroys/recreates the Alpine `x-data` scope, losing the dropdown open/close state. This required the `_alReopen` hack (save service name to `window._alReopen` before POST, read it back in `x-init` after morph).
2. **Idiomorph/Alpine style conflict**: idiomorph strips Alpine's `x-show` inline `display: none` style during morph, requiring a `style="display: none"` hack on the panel div.

The fix: narrow HTMX swap targets to just the fragment that changed. Resource mutations swap only the resources section; level mutations swap only the access levels content. The Alpine `x-data` wrapper is never replaced, so dropdown state is naturally preserved.

## Approach: Django 6.0 `partialdef` (no new files)

Use `{% partialdef %}` to define two named fragments inside `_permission_service_group.html`. The view renders just the needed fragment via `render(request, "template.html#partial_name", context)`.

## Why this works

When htmx does `innerHTML` swap on `#access-levels-{service}`, only the inner content is replaced. The parent `<div x-data="{ open: false }">` stays in the DOM — Alpine's reactive scope survives. New child elements with `@click`, `x-show`, etc. are detected by Alpine's MutationObserver and initialized within the existing scope. The `open` variable retains its current value, so the dropdown stays open if it was open.
