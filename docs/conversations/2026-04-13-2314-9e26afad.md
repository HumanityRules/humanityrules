## Diagnosis

**Root cause: `health_check_grace_period=0` in DEBUG mode (local dev)**

```395:415:devopshero_app/services/infra_customer/deploy_app.py
        # When DOH runs in production (DEBUG=False), use stable settings
        # When developing locally (DEBUG=True), use aggressive settings for fast deploys
        from django.conf import settings
        if settings.DEBUG:
            deregistration_delay = 0
            health_check_interval = 5
            healthy_threshold = 2   # ALB minimum is 2
            min_healthy = 0
            health_check_grace = 0
        else:
            deregistration_delay = 30
            health_check_interval = 10
            healthy_threshold = 2
            min_healthy = 0       # Should it be 100 for "always on, zero downtime"? Make it an option for the user?
            health_check_grace = 60
```

## Timeline of failure (task `2a6fa98a`)

- **22:36:29** — ECS starts task (replaced previous unhealthy task)
- **22:37:09** — Task registered in target group (40s later — image pull + container boot)
- **22:37:14** — Gateway starts loading config inside container
- **22:37:20** — HTTP server ready on port 18789
- **22:37:29** — ALB marks task **unhealthy** ("Request timed out") — only 20s after registration
- **22:37:29** — ECS stops task

Problem: ALB starts health checking immediately on registration (22:37:09) but HTTP server not ready until 22:37:20 — 11s gap. With `health_check_grace=0`, those first 3 failed checks (5s interval × 3 = 15s) → unhealthy → killed.

Eventually task `3724e4` got lucky with timing and became healthy. Service stabilized at 22:38:20, but DOH's 180s timeout already expired → deployment marked as `failed`.

## Fix

Change `health_check_grace` from `0` to `120` in DEBUG mode. Container needs ~50s from task start to HTTP ready. Grace period should cover image pull + boot + gateway startup with buffer:

```python
health_check_grace = 120  # openclaw takes ~50s to start serving HTTP
```
