## Analysis: Your Proposal is Correct and Achievable

Your core insight is right — the four entry points (`new`, `<slug>/`, `<slug>/new/`, `<slug>/resume/`) all converge to the same conversation lookup strategy, making three of them redundant.

### What collapses cleanly

**`deployment_editor` + `deployment_editor_resume` + `deployment_editor_app_new` → single `deployment_editor`**

All three do the same priority chain: find blueprint conversation → find pre-blueprint conversation → create new. The only difference is `app_new` *always* creates when no blueprint exists, while `resume` and the base view try to reuse. Under your model, `/deploy/<slug>/` simply does the lookup-or-create and you're done. This eliminates ~70 lines of view code and the `populate_deployment_entrypoint` logic in `apps.py`.

**`deployment_editor_new` stays but gets simpler**

The pre-app flow (`/deploy/new/?workspace=X&repo=Y`) is genuinely different — no App record exists yet. It stays as-is, but now it's cleaner: always create conversation on first hit, append `&conversation=<id>` to URL, done. No changes needed here beyond keeping it tidy.

### The "New Deployment" button inside the editor

Your idea: a single button in the editor that closes the current conversation and discards any draft, then starts fresh. This replaces both the "Discard Draft" modal flow and the separate "New Deployment" entry point. It works because:

1. Close conversation → mark `ABANDONED`
2. If blueprint is DRAFT/FAILED → mark `DISCARDED`
3. Create fresh conversation for the app
4. Re-render the editor (same URL `/deploy/<slug>/`)

This can be a single POST endpoint (e.g., `deployment_editor_reset`) that does all three steps and returns the editor with a fresh conversation.

### The "Deployment" button on the App card

Your idea: a single button in the app detail that always goes to `/deploy/<slug>/`. Since that endpoint now does the smart lookup-or-create, it always opens "whatever state we're currently in." This replaces the conditional "New Deployment" / "Resume Deployment" label logic in `populate_deployment_entrypoint`.
