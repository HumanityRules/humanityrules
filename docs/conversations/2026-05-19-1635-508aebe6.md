I see the issue. Both extension scripts wrap `switchPanel` and the integrations wrapper does `await refreshAndRender()` before returning — which blocks the outer (webapps) wrapper from toggling off its `showing-webapps` class. During that network fetch, both `showing-webapps` and `showing-integrations` are set on `<main>`, so both views render together for ~as long as the broker fetch takes.

Let me trace it precisely:

**webapps → integrations** (`switchPanel('integrations')`):
1. Outer (webapps wrap) awaits inner (integrations wrap)
2. Inner awaits orig
3. Inner toggles `showing-integrations` ON → now `main` has both `showing-webapps` + `showing-integrations` → **both views render**
4. Inner `await refreshAndRender()` → blocks on `/__doh_broker/integrations` network fetch (the few seconds)
5. Inner returns
6. Outer finally toggles `showing-webapps` OFF → only Integrations remains

The fix is to not block the wrapper return on the network fetch — kick it off without `await`. The class toggles then run synchronously in one tick, so there's no overlap.

## Assistant

Fixed. Cause and fix:

Both extensions wrap `window.switchPanel`. When you click Integrations, the call chain is `webapps-wrapper → integrations-wrapper → orig`. The integrations wrapper was awaiting `refreshAndRender()` (a network call to `/__doh_broker/integrations`) **after** flipping `showing-integrations` ON, but **before** returning to the webapps wrapper, which only flips `showing-webapps` OFF after that await resolves.

Result: for the few seconds the broker fetch took, `<main>` had both `showing-webapps` and `showing-integrations` set, so the CSS revealed both views stacked.

Fix at `template_repos/hermes_agent/webui-extension/doh-integrations.js:531` — kick off `refreshAndRender()` without awaiting it. The class toggles now run in one synchronous tick, so the views never overlap. The fetch still resolves and re-renders the pane in the background.
